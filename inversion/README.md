# Johnsons basal-sliding inversion (ElmerIce)

Adaptation of an existing Hansbreen inversion template (author: JM,
`docu_inv_johnsons/mitest_steady_inv_1.sif`) to Johnsons glacier, reusing
mesh/DEM from the existing Johnsons forward model (author: Inaki,
`johnsons_modelo_TFM_Inaki/`) and observed velocities from `../kriging/`.

## Directory layout

- `johnsons_inversion.sif` - the inversion case itself.
- `mesh/` - mesh and DEM files (tracked).
- `scripts/` - helper scripts (see below).
- `docs/` - diagnostic notes and reference material.
- `results/`, `mesh_Johnson_gmsh_2D_100*/`, `*.log`, `Cost_steady.dat`,
  `CostReg_steady.dat`, `GradientNormAdjoint_steady.dat`,
  `M1QN3_steady.out` - all regenerated by each run, gitignored.
- `camp_<tag>/` - archived campaign runs (own copy of the .sif + results,
  see `docs/running/parallel_runs.md`), so a validated run survives the
  next one overwriting `results/` at the root. E.g. `camp_0609/` (2006-2009
  GPS data, the reference run analyzed in `docs/results/0609/`),
  `camp_1517/` (2014-2018 raw data, tagged by the 3 full years its
  segments represent: 2015-2017).

## Running a case

```bash
cd inversion
rm -rf results && mkdir -p results
rm -f Cost_steady.dat CostReg_steady.dat GradientNormAdjoint_steady.dat M1QN3_steady.out
tmux new-session -d -s inversion "ElmerSolver johnsons_inversion.sif > run_full.log 2>&1"
```

`rm` clears outputs from any previous run: `.vtu` snapshots are numbered
`t0001`, `t0002`... with no run identifier, so old leftovers would
otherwise mix into the new run.

`tmux` keeps the run alive after closing the terminal/VSCode:
```bash
tmux attach -t inversion       # reattach, watch live (Ctrl+B D to detach)
tmux ls                        # list active runs
tmux kill-session -t inversion # stop
```

## Monitoring a run

```bash
bash scripts/check_run.sh
```

Process status, time since last update, cost/gradient trend, iteration
count, backtrack count - warns if backtracks look abnormal. Read-only,
safe to run anytime. See `docs/running/check_run.md` for how to read
each line.

## Plotting convergence history

```bash
python3 scripts/plot_convergence.py   # file names hardcoded at top of the script
```

## Inspecting a field inside a .vtu snapshot

`.vtu` files are XML with binary/base64-encoded data arrays - not readable
with `cat`/`grep`. Use ParaView's own Python interpreter:

```bash
pvpython scripts/inspect_vtu_field.py
```

Edit `FIELD`/`FILES` at the top of the script first (see its docstring for
available field names).

## docs/

- `running/check_run.md` - how to read `check_run.sh` output.
- `running/parallel_runs.md` - how to launch several inversions at once
  (used for the Lambda L-curve sweep).
- `lambda/line_search_diagnosis.md` - diagnosis of the optimizer
  stall encountered on the first two full runs (root cause: `Lambda` too
  weak for the current GPS data density).
- `lambda/lcurve.md` - L-curve sweep justifying the Lambda=1e5 choice.
- `lambda/lambda_justification.md` - write-up of the above in full prose,
  explaining the complete reasoning (vs `lcurve.md`'s short notes).
- `results/0609/velocity_comparison.md` - observed vs modeled surface
  velocity for the campaign 2006-2009 confirmation run (archived in
  `camp_0609/`), with `scripts/compare_velocity.py` and
  `scripts/plot_velocity_compare.py`.
